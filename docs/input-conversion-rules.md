# 하늘키보드 입력 변환 규칙 모음

기준일: **2026-10-28**, Asia/Seoul. 기반 커밋 `813f304831b6dd7de7750950f739d7c1820cfd12` 이후 #104 작업 트리 기준. 현재 코드의 설명과 초창기 아이디어를 함께 모으되, 적용 여부를 구분한다. 실제 동작은 아래 심볼과 테스트를 함께 확인한다.

하늘키보드는 사용자가 친 키를 보관하며 한글을 조합한다. 영어+조사는 입력 중에도 같은 판정으로 미리 표시하고, Space 같은 확정 시점에 사전·한글 구조·앞 단어를 확인해 최종 결과를 정한다. **개별 조건문과 그 순서, 예외, 사전을 묶은 전체가 판정 알고리즘**이다. 조건 하나만으로 언어를 확정하지 않는다.

## 확정 시점과 공통 관문

## 자동 변환의 전체 순서

1. 공통 관문을 통과한다. 숫자가 포함된 입력은 `commitAlphanumeric`에서 등록 제품명/개인 등록명+조사를 먼저 확인하고 기존 제품명·수량 규칙을 적용한다. 아포스트로피는 `commitTextWithApostrophe`의 기존 규칙을 따른다.
2. 일반 알파벳 키열은 **영어+조사 분리**를 먼저 검사한다. 전체 개인 사전 지정과 전체 영어·한글 단어는 분리하지 않고 원래 경로로 넘긴다.
3. 분리가 없으면 `shouldConvertWord`에서 **개인 변환 금지 → 개인 변환 추가 → 수량 뒤 단위 → EnglishDetector** 순으로 판단한다.
4. 변환된 결과와 실제 한글 원문을 짝으로 보관한다. Shift+Space 되돌리기와 다음 단어 문맥에 사용한다. 혼합 단어 뒤는 한국어 문맥으로 취급한다.

개인 금지는 실제 키열 또는 한글 표기로 지정할 수 있다. 전체 지정과 구성 부분 지정의 세부 적용 범위는 아래 조사·단위·축약형 규칙을 따른다.

조사 형태는 역할별 기본형과 결합 순서로 만든다.

- 격조사·연결 조사·보조사와 장소/방향/비교 관계를 구분한다.
- 출발점을 나타내는 관계에는 `부터`를 결합한다. 예: `에서부터`, `로부터`.
- 관계 뒤에는 받침에 맞는 `은/는`, 또는 `도/만`을 결합한다. 예: `이랑은`, `에게는`, `에서부터는`.
- 대화체 `요`를 마지막에 허용한다. 예: `를요`, `에서부터는요`.
- `에선`, `에겐` 같은 축약형은 별도로 명시한다.

실제 입력의 조사를 맞춤법에 맞춰 바꾸지는 않는다. 위 받침 규칙은 허용 형태를 구성할 때만 사용한다. 실행 목록은 코드에서 생성하므로 문서에 전체를 복제하지 않는다.

`form`의 한글 자판 결과 `래그`도 한글 사전에 있어 기본 분리에서는 보호된다. 영어로 사용하려면 개인 변환 추가에 `form`을 넣을 수 있다. 이는 정상 한글을 먼저 보호하는 하늘키보드의 정책이다. `같은건`, `해서`, `하다` 같은 활용형, 영어+일반 한글 단어, 한 글자 변수, 일본어는 이 단계의 대상이 아니다.

## 초창기 조건은 어디에 남아 있는가

초기 조건은 Git 이력과 테스트에 남아 있다. 초기 대화 전체가 보존됐다는 뜻은 아니다.

| 초기 관찰·조건 | 현재 상태 |
|---|---|
| 자음보다 모음이 먼저 나오면 한글로 보기 어렵다 | R1에 반영. `아`의 ㅇ도 초성이다. `ㅠㅠ` 같은 의도적 낱자에는 예외가 있다. ‘99%’는 측정한 정확도로 사용하지 않는다. |
| 자음이 모음보다 많다, 왼손이 오른손보다 많이 쓰인다 | 언어 판정의 아이디어로 보관. 독립적인 비율 점수로는 미구현. `과외`처럼 모음 키가 많은 정상 한글이 있어 단어별 단정은 금물이다. |
| 양손 교대 리듬 | 초기 ROADMAP에 후보로 기록. 현재 실행 판정에는 없음. |
| 자음·모음의 연속, 조합되지 않는 낱자 | MAIN·자음열·R1에 구조 검사와 사전 확인으로 반영. 겹받침·복모음을 보호한다. |
| 직전 영어를 이용한다 | R2, S/C/T와 문맥 차단 규칙으로 반영. 모든 영어 뒤에서 모든 한글을 바꾸지는 않는다. |
| 쓰이지 않는 한글 음절 | R3에 반영. 표준 문자 집합 밖이라는 사실만으로 언어를 확정하지 않는다. |

## Vim과 터미널

Vim은 입력 모드에서 글자를 쓰고 일반 모드에서 같은 키를 명령으로 쓴다. 일반 모드에는 키가 즉시 전달되는 것이 맞다. **현재 하늘키보드는 Vim 모드를 감지하지 않는다. 이번 조사 분리도 Vim을 자동 감지해 끄는 기능을 추가하지 않는다.**

앱별 자동 변환 OFF는 조사 분리도 끄지만 두벌식 조합 자체를 끄지는 않는다. 따라서 이것만으로 Vim 명령 전달을 보장하지 않는다. Vim 명령 작업은 ABC 입력 소스를 쓰고, 향후 연동에서는 입력 모드 외 키 통과를 별도로 다룬다. Terminal·Ghostty의 확정 글자 교체 제한도 유지된다.
