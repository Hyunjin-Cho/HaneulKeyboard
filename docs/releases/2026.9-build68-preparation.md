# 빌드 68 — 라이선스·보안·문서 준비

기준일: **2026-10-10**. 기준 HEAD `cdd26cdf87cea727c1604cc01dcae502191eecc1` + 로컬 변경. 앱 버전 **2026.9 (68)**. 정식 날짜 버전을 미리 부여하지 않았다.

## 현재 상태

사용자가 승인한 순서 중 **2번 라이선스, 3번 보안, 5번 문서/GitHub 정리**의 로컬 테스트 후보다. 2026-10-10 사용자가 커밋·푸시·PR 머지까지 승인했다. 이 문서는 로컬 검증 기록이며, 게시·CI·머지의 최신 상태는 [PR #79](https://github.com/Hyunjin-Cho/HaneulKeyboard/pull/79)에서 확인한다. 최신 설치본 검증·공증·정식 배포는 별도 단계다. 에이전트 소집 없이 루트 Codex가 구현과 자체 검토를 수행했다.

- 앱 코드를 **Apache License 2.0 + NOTICE**로 전환했다. NOTICE에 원본 이름·저작권·주소를 기록하고, 이전 MIT 고지와 사전/글꼴의 개별 라이선스를 보존했다.
- 메인 앱, 내장 IME, 단독 IME에 LICENSE·NOTICE·ACKNOWLEDGEMENTS.md·HaneulKeyboard-MIT-legacy.txt를 동봉한다. 배포 스크립트와 CI에서 원본 바이트까지 대조한다.
- #66: `UpdateTransport.receive`가 JSON **2 MiB**, ZIP **200 MiB** 한도를 수신 도중 적용한다. 헤더와 실제 청크를 따로 검사하고, ZIP을 디스크로 직접 쓰며 실패·취소 때 부분 파일을 제거한다. HTTPS/호스트 제한을 리다이렉트마다 적용한다.
- #67: `BundleTrust`가 Apple 인증서 체인과 실행 중 앱의 Team을 함께 요구한다. 호스트와 후보 모두 검사하며 포크는 자신의 Apple Team으로 서명할 수 있다. 업데이트의 공식 Team 고정 검사는 유지한다.
- #68: Debug도 기본 서명 검사를 한다. 생략은 `haneul.debugSkipTeamCheck`, 시험 저장소는 `haneul.updateAllowUnofficialRepo`를 명시적으로 허용한 경우만 가능하다. Release에서는 우회 설정을 읽지 않는다.
- README 한/영·감사의 글·개인정보·수동/배포 체크리스트를 맞췄다. 공개 문서와 구현 변경은 PR #79에서 함께 관리한다.
- GitHub CI를 `disabled_manually`에서 **active**로 되돌렸다. 로컬 workflow에 사전 감사·보안 검사·안내 입력 검사·번들 고지 검사를 추가했다. **CI 활성화와 로컬 검사는 원격 CI 통과를 뜻하지 않는다.** 대상 커밋의 실행 결과는 PR #79의 Checks에서 확인한다.

서명 fixture는 기존 빌드 62 ZIP을 임시 폴더에 풀어 사용했다. 정상 Apple 서명 앱/IME 허용, 다른 Team·미서명 후보·훼손한 복사본 거부를 확인했다. 자체 서명 인증서를 새로 발급하는 시험과 최신 빌드의 실제 설치/업데이트 왕복은 수행하지 않았다.

수신 테스트는 실제 URLSession delegate에 가짜 HTTP 응답을 넣는다. 알려진/없는/거짓 Content-Length, 한도 정확 일치/초과, 전체 수신 전 취소, 파일 쓰기·기존 파일 보존, 통신 실패·작업 취소, 허용/금지 리다이렉트, 실패 뒤 정상 확인 복구를 검증한다. 실제 GitHub CDN에서 거대 파일을 다운로드하는 시험은 아니다.

검증 로그는 로컬 `.tmp/release-prep-235/`의 `core.log`, `native.log`, `updater-signed.log`, `dictionary-audit.log`, `wordlist-smoke.log`, `final-*-build.log`, `*-notices.log`, `bundle-audit.json`에 보관한다.
