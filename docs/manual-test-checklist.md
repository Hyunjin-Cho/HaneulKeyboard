## 메뉴바와 설정

- [ ] 앱 실행 후 메뉴바 **오른쪽** 상태 영역에 HaneulKeyboard `한` 또는 `A` 아이콘이 나타난다.
- [ ] 아이콘을 클릭하면 메뉴가 아이콘 아래의 정상 위치에 열린다(화면 왼쪽 위 등 엉뚱한 위치에 열리지 않는다).
- [ ] `설정...`을 누르면 설정 창이 열리고 조작 가능하다.
- [ ] 설정 창을 닫은 뒤 다시 `설정...`을 누르면 창이 정상적으로 재열린다.

## 온보딩

- [ ] 첫 실행 시 `시작하기...` 온보딩을 열고 모든 단계를 완료할 수 있다.
- [ ] 온보딩 완료 후 메뉴에 `시작하기 다시 보기...`가 나타난다.
- [ ] `시작하기 다시 보기...`로 온보딩을 재열고 단계 이동·닫기가 정상 동작한다.

## 입력 소스와 전환 키

- [ ] macOS 입력 메뉴에서 하늘키보드를 선택하면 메뉴바 표시가 `한`으로 갱신된다.
- [ ] ABC 입력 소스로 바꾸면 메뉴바 표시가 `A`로 갱신된다.
- [ ] 입력 소스를 여러 번 바꿔도 `한`/`A` 표시가 누락·지연 없이 현재 상태와 일치한다.
- [ ] 하늘키보드 활성 상태에서 Caps Lock을 짧게 누르면 한↔영 입력 소스가 전환되고 이어서 입력한 문자가 올바른다.
- [ ] Caps Lock을 길게 누르는 macOS 대문자 Caps Lock 동작과 짧게 누르는 한영 전환이 구분된다.
- [ ] **Caps Lock 시스템 옵션 OFF** (#56, 2026-09-21): 시스템 설정 → 키보드 → 입력 소스의 "Caps Lock으로 ABC 전환" 옵션을 **꺼둔** 상태에서 Caps Lock을 눌러도 언어가 바뀌지 않는다(바뀌면 OS 버그 — 우리는 `TICapsLockLanguageSwitchCapable`로 OS에 위임하므로 우리 코드로 못 고친다. Apple Community 2025-09 리포트: 옵션이 꺼져 있어도 Caps Lock이 언어를 바꿈). 확인 후 옵션을 다시 켠다.
- [ ] 영타 자동 변환 대상 단어를 확정한 뒤 Shift+Space를 누르면 영타↔한글 결과가 되돌려지고, 다시 누르면 역방향으로 토글된다.
- [ ] 토글 대상이 아닌 문장에서 Shift+Space가 인접 텍스트를 훼손하지 않는다.
- [ ] **ABC 없음** (#45, 2026-09-20): 입력 소스에서 ABC를 빼고 U.S.(또는 British·Dvorak) 같은 다른 영문 자판만 둔 상태에서 메뉴 "영어로 전환"을 누르면 **그 자판으로** 전환되고 메뉴바가 `A`가 된다.
- [ ] **영문 자판 없음**: 영문 자판이 하나도 켜져 있지 않을 때 "영어로 전환"을 누르면 "영어로 전환하지 못했어요" 알림이 뜬다(조용히 실패하지 않는다). 하늘키보드를 입력 소스에서 뺀 상태에서 "한국어로 전환"을 누르면 "한국어로 전환하지 못했어요" 알림이 뜬다.

### 터미널 — Shift+Space 되돌리기 미지원 (#30)

터미널에 입력된 글자는 즉시 셸 프로세스 소유가 되어 앱조차 IME 요청으로 회수할 수단이 없다. 따라서 되돌리기는 **원리적으로 불가능**하며, 이 항목들은 "되게 만드는 것"이 아니라 **실패가 조용하고 일관되게 끝나는지**를 확인한다. (2026-09-21, #54: 되돌리기 키를 다른 조합으로 바꿔도 같다 — 키가 아니라 클라이언트의 문제.)

- [ ] Terminal.app에서 영타 변환 후 Shift+Space를 여러 번 눌러도 텍스트가 훼손되지 않는다(변화 없음이 정상).
- [ ] Ghostty에서도 같은 동작 — 되돌려지지 않고, **스페이스가 대신 끼어들지도 않는다**(과거엔 스페이스만 늘어났다).
- [ ] 두 터미널의 동작이 서로 같다.
- [ ] 터미널에서 영타 자동 변환 자체는 정상 동작한다(되돌리기만 불가).
- [ ] 터미널에서 오변환이 나면 백스페이스로 지우고 다시 칠 때 재변환되지 않는다(수동 복구 경로).
- [ ] (#54) 설정 → "되돌리기 키" 절 아래에 터미널에서는 되돌리기가 안 된다는 안내 문구가 보이고, README "알려진 문제"에도 같은 항목이 있다.

### 모든 단어 되돌리기 — 수동 한↔영 토글 (#15, 2026-09-21)

되돌리기 키가 이제 **커서 앞 단어 전부**에 듣는다(자동 변환 여부와 무관). 자동 테스트는 순수 함수(`ManualToggle`·`KoreanComposer.wordBeforeCursor`, 완성형 11,172자 왕복 포함)까지만 본다. **실제 키 이벤트·`selectedRange`/`attributedSubstring` 왕복·앱별 범위 교체 동작은 사람이 확인한다. 구현 시점(2026-09-21) 실기기 미검증.** 설정 키: `defaults read com.hyunjincho.inputmethod.haneul haneul.manualToggleAllWords` (없으면 기본 켜짐).

- [ ] TextEdit 한글 모드에서 `work` + 스페이스 → `재가 `(우리말샘 veto로 변환 안 됨). 여기서 되돌리기 키를 누르면 `work `가 된다.
- [ ] 이어서 한 번 더 누르면 `재가 `로 돌아오고, 계속 눌러도 두 상태를 왔다갔다 한다.
- [ ] `m5` + 스페이스 → `ㅡ5 `. 되돌리기 키 → `m5 `(숫자 `5`는 제자리에 그대로). 다시 누르면 `ㅡ5 `.
- [ ] `k3` → `ㅏ3` 도 같은 방식으로 양방향.
- [ ] 스페이스 없이 `work`까지만 친 상태(조합 중, 화면에 `재가`)에서 되돌리기 키를 누르면 **그 한 번은 확정 + 스페이스**로 끝나고, 그다음 누름부터 `work`로 토글된다.
- [ ] **되돌리기 우선**: `apple` + 스페이스 → `apple `(자동 변환됨). 되돌리기 키 → `메ㅔㅣㄷ `(종전 동작 그대로, 수동 경로로 새지 않는다).
- [ ] 자동 변환을 되돌린 뒤 다시 누르면 `apple `로 돌아온다(종전 동작 그대로).
- [ ] 정상 한국어 단어도 대상이다 — `안녕 ` 뒤에 되돌리기 키를 누르면 `dkssud `가 되고, 다시 누르면 `안녕 `으로 돌아온다(의도된 동작).
- [ ] 문장 중간에서도 **마지막 단어만** 바뀐다: `go work ` → `go 재가 `(앞의 `go`는 그대로).
- [ ] 드래그로 글자를 선택한 상태에서 되돌리기 키를 누르면 토글하지 않는다(선택을 지우고 스페이스가 들어가는 앱의 기본 동작).
- [ ] 빈 입력 칸(커서가 맨 앞)에서 누르면 **스페이스가 그냥 입력된다** — 키가 삼켜지지 않는다.
- [ ] 이모지·한자·한글+영어 혼합(`재work`) 뒤에서 누르면 아무것도 바뀌지 않고 스페이스가 입력된다.
- [ ] 설정 → "모든 단어 되돌리기"를 **끄면** `재가 ` 뒤에서 되돌리기 키를 눌러도 바뀌지 않고(스페이스만 입력), `apple` 자동 변환 되돌리기는 여전히 동작한다. 설정 창을 닫지 않아도 즉시 반영된다.
- [ ] 터미널(Terminal.app·Ghostty)에서 `재가 ` 뒤에 되돌리기 키를 눌러도 텍스트가 훼손되지 않는다(#30과 같은 구조적 제약 — 변화 없음이 정상).

- [ ] 시스템 설정 등 네이티브 비밀번호 칸에서는 되돌리기 키를 눌러도 아무 일도 일어나지 않는다(secure input 가드).
- [ ] "전체 제거" 뒤 `defaults read com.hyunjincho.inputmethod.haneul`에 `haneul.manualToggleAllWords`가 남지 않는다.
- [ ] 설정 창(580×600 고정)에서 "모든 단어 되돌리기" 절이 "되돌리기 키" 절 바로 아래에 보이고, 토글이 키보드·VoiceOver로 조작된다.

### 영타 축약형 — 아포스트로피 (#34, 2026-09-19)

조합 중의 `'`는 이제 경계가 아니라 **단어 내부 문자**다(marked text에 그대로 보인다). 자동 테스트는 composer 층까지만 검증하므로, 실제 앱에서 `'` 키가 IME까지 도달하는지·마크드 텍스트가 어떻게 그려지는지는 사람이 확인한다. 앱마다 스마트 따옴표(`'`→`’`) 치환이 다르므로 **최소 두 종류의 앱**에서 본다.

- [ ] TextEdit에서 한글 모드로 `i'm don't` 를 치면 `i'm don't` 로 변환된다.
- [ ] Chrome 주소창이 아닌 웹 입력창(예: 검색창·댓글창)에서도 같은 결과가 나온다.
- [ ] 치는 동안 `'`가 조합 중 글자(marked text) 안에 보인다 — `ㅑ'` → `ㅑ'ㅡ`.
- [ ] `i'm` 확정 직후 Shift+Space를 누르면 `ㅑ'ㅡ` 로 통째로 되돌려지고, 다시 누르면 `i'm` 으로 돌아온다.
- [ ] `it's a test` 처럼 축약형 뒤 단어도 영어 문맥으로 이어져 변환된다.
- [ ] 한글 입력 중 `안녕'하세요` 를 치면 그대로 `안녕'하세요` 로 남는다(오변환 없음).
- [ ] 여는 따옴표로 시작하는 `'안녕` 이 그대로 입력된다.
- [ ] `'` 를 친 뒤 Backspace를 누르면 `'` 만 지워지고 앞 글자는 남아 조합이 이어진다.
- [ ] `ㅑ'` 까지 친 상태에서 다른 곳을 클릭하면 화면에 보이던 `ㅑ'` 가 그대로 확정된다.
- [ ] 설정에서 영타 자동 변환을 끄면 `i'm` 이 `ㅑ'ㅡ` 로 남는다.

### 개인 사전 (#53, 2026-09-21)

## 앱 삭제 ↔ IME 연동 (#32, 2026-09-19)

자동 테스트는 판단 함수(`OrphanDecision`)만 검증한다. 실제 삭제·비활성화·종료는 아래에서 사람이 확인한다. 로그: `/usr/bin/log show --predicate 'subsystem == "com.hyunjincho.haneulkeyboard" AND category == "orphan"' --last 30m`.

> ⚠️ **전제 조건 (2026-09-20, #43 · 리뷰 F-4)** — 개발 머신에서는 이 절이 **그냥은 통과할 수 없다.** IME는 후보 경로를 LaunchServices(`urlsForApplications`)에서도 가져오는데, `.build/*DerivedData*/Build/Products/*/HaneulKeyboard.app` 같은 빌드 산출물이 등록돼 있고 디스크에 실존하면 휴지통 밖에 살아 있는 복사본으로 세어 **항상 `present`** 가 된다(2026-09-20 Mac Studio 실측: 메인 앱 bundle ID로 10개 경로, 그중 9개가 `.build` 산출물). 그러면 앱을 휴지통에 버려도 자기 정리는 절대 발동하지 않고 "연동이 안 된다"는 오판이 난다. 검증 전에:
> 1. 저장소 안 `.build/*DerivedData*` 산출물을 지우거나(`rm -rf`는 오너 결정) `lsregister -u <산출물 경로>`로 등록만 뺀다. (2026-09-21 #52: `scripts/build_notarize_install.sh`는 끝날 때 자기 산출물 `.build/DerivedData/Build/Products/Release/`의 등록을 자동으로 뺀다 — 다른 DerivedData·Debug 산출물은 여전히 손으로.)
> 2. 확인 — 아래 프로브가 `/Applications/HaneulKeyboard.app` **하나만** 돌려줘야 한다 (프로브가 확인 — scripts/postinstall_probe.sh 4번):
>    `swift -e 'import AppKit; NSWorkspace.shared.urlsForApplications(withBundleIdentifier: "com.hyunjincho.haneulkeyboard").forEach { print($0.path) }'`
> 3. 최종 사용자 머신에는 DerivedData가 없으므로 이 전제는 개발 머신 전용이다(제품 결함 아님).

- [ ] **복원 유예**: 앱을 휴지통에 버렸다가 **2분 안에 "제자리에 놓기"**로 되돌리면 IME가 사라지지 않고 설정도 남아 있다.

## 자동 업데이트 (#19, 2026-09-21)

자동 테스트(`Tests/ComposerTests.swift`의 「자동 업데이트 판단」 묶음)는 **판단만** 검증한다 — CalVer 비교, 자산 선택, 허용 호스트, 24시간 throttle, 검증 5종 합성, 교체 전략. **네트워크 요청·다운로드·서명 검증 실행·앱 교체·재실행·IME 갱신은 자동으로 확인할 방법이 없어 전부 아래에서 사람이 본다.** 2026-09-21 구현 시점에 이 절은 **한 줄도 실기기 검증되지 않았다.**

> **준비 — 시험용 릴리스**: 진짜 릴리스를 올리지 않고 끝까지 보려면 Debug 빌드의 시험 훅을 쓴다.
> `defaults write com.hyunjincho.haneulkeyboard haneul.updateRepoOverride Hyunjin-Cho/HaneulKeyboard-updatetest`
> (Release 빌드에는 이 키를 읽는 코드가 **컴파일되지 않는다** — Debug 전용.) 시험 저장소에는 현재 앱보다 높은
> tag(예: `2026.99`)와 **같은 이름 규칙의 자산** `HaneulKeyboard_2026.99.zip`(서명·공증까지 끝낸 진짜 빌드)을 올려 둔다.
> 끝나면 `defaults delete com.hyunjincho.haneulkeyboard haneul.updateRepoOverride`.
> 요청이 실제로 나가는지 / 안 나가는지는 `/usr/bin/nettop -p <pid>` 또는 Charles·Proxyman 같은 도구로 본다.
> 로그: `/usr/bin/log show --predicate 'subsystem == "com.hyunjincho.haneulkeyboard"' --last 30m | grep -i update`

### 검증 실패 — 기존 앱이 그대로 남는가 (가장 중요)

> 각 항목 뒤에 **`/Applications/HaneulKeyboard.app`의 빌드 번호가 그대로인지** 반드시 확인한다.

- [ ] **서명 깨뜨리기**: 시험 저장소 자산을 *서명하지 않은* 또는 *ad-hoc 서명한* 빌드로 바꾼 뒤 [업데이트] → "검증 실패로 설치하지 않았어요: …" 가 뜨고 **기존 앱이 그대로**다.
- [ ] **공증 없음**: 서명은 했지만 **노타리·staple 하지 않은** zip → `Gatekeeper(노타리) 거부`로 실패하고 기존 앱이 그대로다.
- [ ] **다른 앱**: 자산을 전혀 다른 앱(예: 계산기)의 zip으로 바꾸면 `번들 ID가 HaneulKeyboard가 아님`으로 실패한다.
- [ ] **다운그레이드**: 시험 저장소 tag만 높이고 자산은 **현재보다 낮은 빌드**의 zip으로 두면 `버전이 현재보다 높지 않음`으로 실패한다.
- [ ] **파일 손상**: 자산 zip의 바이트 일부를 훼손하면 "압축 해제 실패" 또는 크기 불일치로 멈추고 기존 앱이 그대로다.
- [ ] 위 실패 뒤에도 **메뉴바 앱이 계속 살아 있고** 설정 창에서 다시 "지금 확인"을 할 수 있다.

### 교체 · 재실행

- [ ] 정상 자산으로 [업데이트] → "다운로드 중…" → "서명·노타리 검증 중…" → "설치 중…" 순으로 문구가 바뀐 뒤 앱이 **스스로 다시 열린다**(메뉴바 아이콘이 잠깐 사라졌다 돌아온다).
- [ ] 재실행된 앱의 설정 → "현재 버전"이 **새 버전·새 빌드**를 가리킨다.
- [ ] `/Applications` 안에 `.HaneulKeyboard.app.update-…` 나 `.HaneulKeyboard.app.old-…` 같은 **찌꺼기가 남아 있지 않다**.
- [ ] 교체 중 `~/Library/Preferences/com.hyunjincho.*` 설정(개인 사전·되돌리기 키·앱별 끄기)이 **그대로 남아 있다**.
- [ ] **응용 프로그램 폴더 밖**에서 실행한 앱(예: 다운로드 폴더 사본)에서 [업데이트]를 누르면 "자동 업데이트는 응용 프로그램 폴더(/Applications)에 설치된 앱에서만 할 수 있어요"라며 **중단**되고, `/Applications`의 앱은 건드려지지 않는다.
- [ ] **root 소유 설치본**(`sudo chown root /Applications/HaneulKeyboard.app`)에서 [업데이트] → **관리자 암호 창**이 뜬다. **취소**하면 "앱 교체 실패 — 기존 앱은 그대로예요"가 뜨고 실제로 기존 앱이 그대로다. 암호를 넣으면 교체·재실행된다.

- [ ] 사용자 도메인(`~/Library/Input Methods`) 설치본: 새 버전으로 재실행되면 **자동으로 IME가 갱신**된다 — `HaneulKeyboardIM.app`의 `CFBundleVersion`이 새 빌드와 같아지고, 로그에 `IME refreshed to bundled build …`가 남는다. **한글 입력이 갱신 뒤에도 정상 동작한다**(입력기가 죽은 채로 남지 않는다).
