### 터미널 — Shift+Space 되돌리기 미지원 (#30)

터미널에 입력된 글자는 즉시 셸 프로세스 소유가 되어 앱조차 IME 요청으로 회수할 수단이 없다. 따라서 되돌리기는 **원리적으로 불가능**하며, 이 항목들은 "되게 만드는 것"이 아니라 **실패가 조용하고 일관되게 끝나는지**를 확인한다. (2026-09-21, #54: 되돌리기 키를 다른 조합으로 바꿔도 같다 — 키가 아니라 클라이언트의 문제.)

- [ ] Terminal.app에서 영타 변환 후 Shift+Space를 여러 번 눌러도 텍스트가 훼손되지 않는다(변화 없음이 정상).
- [ ] Ghostty에서도 같은 동작 — 되돌려지지 않고, **스페이스가 대신 끼어들지도 않는다**(과거엔 스페이스만 늘어났다).
- [ ] 두 터미널의 동작이 서로 같다.

### 영타 축약형 — 아포스트로피 (#34, 2026-09-19)

조합 중의 `'`는 이제 경계가 아니라 **단어 내부 문자**다(marked text에 그대로 보인다). 자동 테스트는 composer 층까지만 검증하므로, 실제 앱에서 `'` 키가 IME까지 도달하는지·마크드 텍스트가 어떻게 그려지는지는 사람이 확인한다. 앱마다 스마트 따옴표(`'`→`’`) 치환이 다르므로 **최소 두 종류의 앱**에서 본다.

- [ ] TextEdit에서 한글 모드로 `i'm don't` 를 치면 `i'm don't` 로 변환된다.
- [ ] Chrome 주소창이 아닌 웹 입력창(예: 검색창·댓글창)에서도 같은 결과가 나온다.
- [ ] 치는 동안 `'`가 조합 중 글자(marked text) 안에 보인다 — `ㅑ'` → `ㅑ'ㅡ`.
- [ ] `i'm` 확정 직후 Shift+Space를 누르면 `ㅑ'ㅡ` 로 통째로 되돌려지고, 다시 누르면 `i'm` 으로 돌아온다.
- [ ] `it's a test` 처럼 축약형 뒤 단어도 영어 문맥으로 이어져 변환된다.
- [ ] 한글 입력 중 `안녕'하세요` 를 치면 그대로 `안녕'하세요` 로 남는다(오변환 없음).
- [ ] 여는 따옴표로 시작하는 `'안녕` 이 그대로 입력된다.
- [ ] `'` 를 친 뒤 Backspace를 누르면 `'` 만 지워지고 앞 글자는 남아 조합이 이어진다.
- [ ] `ㅑ'` 까지 친 상태에서 다른 곳을 클릭하면 화면에 보이던 `ㅑ'` 가 그대로 확정된다.
- [ ] 설정에서 영타 자동 변환을 끄면 `i'm` 이 `ㅑ'ㅡ` 로 남는다.

- [ ] **자동 변환 끔**: "영타 자동 변환"을 끄면 변환 추가 목록의 단어도 변환되지 않는다(마스터 스위치 우선).

### 단어 제안 (#55, 2026-09-21)

자동 테스트는 **URL 생성 순수 함수**(`WordSuggestion.issueURL` — 제목·본문·인코딩·8000자 상한)까지만 검증한다. **브라우저가 실제로 열리는지, GitHub이 제목·본문·라벨을 그대로 채워 보여주는지는 자동으로 못 보므로 여기서 사람이 확인한다.** ⚠️ 아래는 **전부 미검증**이다 — 구현 세션에서 실기기 확인을 하지 못했다(브라우저를 열지 않기로 한 제약).

## 앱 삭제 ↔ IME 연동 (#32, 2026-09-19)

자동 테스트는 판단 함수(`OrphanDecision`)만 검증한다. 실제 삭제·비활성화·종료는 아래에서 사람이 확인한다. 로그: `/usr/bin/log show --predicate 'subsystem == "com.hyunjincho.haneulkeyboard" AND category == "orphan"' --last 30m`.

> ⚠️ **전제 조건 (2026-09-20, #43 · 리뷰 F-4)** — 개발 머신에서는 이 절이 **그냥은 통과할 수 없다.** IME는 후보 경로를 LaunchServices(`urlsForApplications`)에서도 가져오는데, `.build/*DerivedData*/Build/Products/*/HaneulKeyboard.app` 같은 빌드 산출물이 등록돼 있고 디스크에 실존하면 휴지통 밖에 살아 있는 복사본으로 세어 **항상 `present`** 가 된다(2026-09-20 Mac Studio 실측: 메인 앱 bundle ID로 10개 경로, 그중 9개가 `.build` 산출물). 그러면 앱을 휴지통에 버려도 자기 정리는 절대 발동하지 않고 "연동이 안 된다"는 오판이 난다. 검증 전에:
> 1. 저장소 안 `.build/*DerivedData*` 산출물을 지우거나(`rm -rf`는 오너 결정) `lsregister -u <산출물 경로>`로 등록만 뺀다. (2026-09-21 #52: `scripts/build_notarize_install.sh`는 끝날 때 자기 산출물 `.build/DerivedData/Build/Products/Release/`의 등록을 자동으로 뺀다 — 다른 DerivedData·Debug 산출물은 여전히 손으로.)

>    `swift -e 'import AppKit; NSWorkspace.shared.urlsForApplications(withBundleIdentifier: "com.hyunjincho.haneulkeyboard").forEach { print($0.path) }'`
> 3. 최종 사용자 머신에는 DerivedData가 없으므로 이 전제는 개발 머신 전용이다(제품 결함 아님).

## 자동 업데이트 (#19/#83, 2026-10-08)

`Tests/ComposerTests.swift`는 버전·자산·주소·주기·교체 판단을 검증한다. `scripts/run_updater_tests.sh`는 실제 Updater와 URLSession delegate에 가짜 HTTP 응답을 넣어 알림·저장·재시도, JSON/ZIP 수신 중 한도, 취소/실패 파일 정리, 리다이렉트를 Debug/Release 모두 검사한다. 선택한 기존 Developer ID 앱을 `HANEUL_SIGNED_FIXTURE`로 주면 Security.framework의 정상/다른 Team/미서명 후보도 확인한다. **설치된 최신 앱의 전체 업데이트·재실행·IME 갱신은 아래 실기가 남아 있다.**

- [ ] 4단계 굵은 ‘터미널은 Shift + Space 단축키가 작동하지 않아요.’가 보인다. 다른 단축키로 설정하면 이름도 바뀐다.
- [ ] 1단계에서 설치 전에 `메ㅔㅣㄷ → apple` 기능 미리보기가 보인다. 시연 뒤에도 전후 결과가 남고, 다시 보기로 재생된다. 시스템의 동작 줄이기에서는 정지된 전후 결과를 보여준다.
- [ ] 3·4단계 손글씨 화살표가 입력칸을 가리킨다. 입력하면 Space 또는 현재 수동 변환 단축키 안내로 바뀌며, 빈 칸으로 되돌리면 화살표가 돌아온다.
- [ ] 실제 한글 조합에서 apple로 바뀌었을 때 성공 안내가 나온다. 영문 apple을 바로 입력·붙여넣기한 것만으로 자동 변환 성공이라고 표시하지 않는다.
- [ ] 안내 창 활성/비활성 모두 종이가 불투명하며 배경 화면 무늬가 드러나지 않는다.
- [ ] 설정·후원 창의 Glass에서는 바탕화면의 색만 부드럽게 남고 무늬는 흐려진다. 안내는 종이를 유지한다.
- [ ] 설정·후원 창의 Glass 배경이 이전보다 한 톤 어두운 중성 회색으로 보인다. 밝은 모드 8%/어두운 모드 4% 검정 레이어는 배경에만 적용되어 버튼·글자 색과 입력 동작에 영향을 주지 않는다. Solid/투명도 줄이기에는 적용되지 않는다.
- [ ] 2단계 입력 소스 카드의 경로·등록 상태를 읽기 쉽고 세 가지 색으로 순서를 구별할 수 있다.
- [ ] 2단계 카드의 숫자·아이콘이 밝은 모드에서 먹색이며 아이콘 선이 또렷하다. 다크 모드에서는 밝은 본문색으로 바뀌어 배경에 묻히지 않는다. 진행 버튼과 단계 점의 하늘색은 유지된다.
- [ ] Glass/Solid 전환·창 다시 열기 후 설정이 유지되고 연습 중 글자·커서·단계가 초기화되지 않는다.
- [ ] 3·4단계 한글 조합 중 안내 문구와 글자가 겹치지 않는다. Shift+Space 반복에도 아래 개인 사전 카드 크기가 변하지 않는다.
- [ ] 4단계 apple·Shift+Space 안내, 별도 터미널 제한, hola 예시와 5단계 후원 링크 왼쪽 하트가 보인다.

## 2026.9(53) — 단위 표기 (#82, 2026-10-07)

최초 빌드 53에서 코어 2,496개/AppKit 입력칸 49개 검사는 통과했고 설치본 IMK 실기는 남아 있다. 아래는 한글 모드에서 키를 직접 누르고 Space로 확정한다. 최신 빌드에서는 아래 추가 항목도 검사한다.

- [ ] 앱/입력기 모두 빌드 53. 기존 52에서 새 입력기 갱신을 인식한다.
- [ ] `oz`, `km`, `kg`, `cm`, `100ml`, `35mm`, `1.25ml`, `100 ml`, `1.25 kg`.
- [ ] 영상/디지털: `24fps`, `48kHz`, `100Mbps`, `10GB`, `10dB`. 입력 대소문자 유지.
- [ ] 단독 `ml=ㅢ`, `mm=ㅡㅡ`, `cc=ㅊㅊ`, 한글 수량 `5개`, `3명`, `10이`, `3치`는 보존.
- [ ] `100ml`과 `1.25ml`을 확정한 직후 Shift+Space로 숫자/소수점까지 포함해 양방향 되돌리기. 터미널 제외.
- [ ] `100 ml`을 확정하고 되돌렸다 다시 바꾼 후 `새`를 입력해 영어로 잘못 바뀌지 않는지 확인.
- [ ] `1.5ml` 되돌린 항목의 ‘금지’가 실제로 적용된다. 단위 `ml` 자체를 금지하면 다른 수량의 ml도 보존.
- [ ] 숫자/소수점/단위 중간 Backspace, 포커스 이동, Caps Lock, 줄바꿈에서 유실/중복 없음.
- [ ] 자동 변환 OFF 및 앱별 OFF에서 숫자 단위도 자동 변환하지 않는다.

정확한 범위·예외·재현 명령: [단위 지원 문서](measurement-units.md). 최초 빌드 53에서는 174개 표기 중 169개가 숫자 조건에서 변환되며 cl/dl/dm/em/wk는 정상 한글 보호로 보류한다.
